# HeadCore 新闻与公开信息来源策略

## 1. 结论

不存在一个同时覆盖国内外、长期免费、稳定、可用于正式产品并提供全文的新闻 API。HeadCore 应采用混合来源：

1. API 或 RSS 只负责发现候选信息。
2. 国内政策、统计和财经信息优先使用政府或机构官方页面。
3. 普通 HTTP 能解析时直接解析，不启动浏览器渲染。
4. 所有来源最终只产生 `WorldObservation`，不能直接改写人格、关系或长期记忆。

## 2. 第一批候选来源

候选来源登记在 `data/world/sources.json`，默认全部关闭。

| 来源 | 类型 | 适合内容 | 限制 |
| --- | --- | --- | --- |
| [GDELT DOC API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/) | 免费、免 Key API | 国际新闻发现、跨语言检索 | 适合发现和链接，不等于获得原站全文授权 |
| [联合国新闻 RSS](https://news.un.org/feed/subscribe/en/news/all/rss.xml) | 官方 RSS | 国际组织、冲突、人道和政策新闻 | 主题范围有限，不能代替综合新闻 |
| [WHO 新闻 RSS](https://www.who.int/rss-feeds/news-english.xml) | 官方 RSS | 全球健康与公共卫生 | 只覆盖 WHO 领域 |
| [中国政府网最新政策](https://www.gov.cn/zhengce/zuixin/) | 官方页面同域 JSON | 国务院政策和文件 | 已实现元数据 Adapter；只保留标题、日期、官方链接，正文不采集，默认关闭 |
| [国家统计局最新发布](https://www.stats.gov.cn/sj/zxfb/) | 官方网页 | 宏观经济、人口、统计数据 | 更新频率较低，适合按小时检查 |
| [中国人民银行发布](https://www.pbc.gov.cn/goutongjiaoliu/113456/113469/index.html) | 官方网页 | 货币政策与金融信息 | 当前 robots 对通用客户端为 `Disallow: /`，禁止自动采集，只能人工链接或取得明确授权 |
| [证监会发布](https://www.csrc.gov.cn/csrc/c100028/common_list.shtml) | 官方网页 | 资本市场政策与监管信息 | `robots.txt` 当前返回普通 HTML，无法确认自动访问规则，保持待审核 |
| [国家发展改革委发布](https://www.ndrc.gov.cn/xwdt/xwfb/) | 官方网页 | 宏观政策、产业与价格信息 | `robots.txt` 当前返回 403，保持待审核 |

可选但不作为首批依赖：Guardian Open Platform 需要开发者 Key 并受使用条款约束；NewsAPI 的免费开发计划通常不适合作为正式部署的数据源。启用时必须重新阅读当日的官方定价和授权说明，不能把“可以免费注册”理解为“可无限制商用”。

2026-07-17 的访问规则检查还发现：国家统计局没有可确认的 `robots.txt`（返回 404）。这些结果会变化，正式启用前必须重新检查。清单中的 `automation_policy` 用来阻止误开：`api`/`feed` 表示有结构化机器入口，`review_required` 表示尚未完成审核，`robots_blocked` 表示当前禁止自动采集，只有人工确认后的 `approved_page` 才能启用普通页面。

中国政府网最新政策列表页自身请求 `https://www.gov.cn/zhengce/zuixin/ZUIXINZHENGCE.json`。当前 Adapter 复用该结构化列表，不渲染浏览器，也不访问每篇正文。网站声明限制商业性原版原式转载，因此来源仍保持 `review_required` 和 `legal_approved=false`；代码完成不等于已取得内容再利用授权。

## 3. API、RSS 与 HTTP 的优先顺序

```text
API/RSS -> 普通 HTTPS -> 人工补录
```

- API/RSS：结构稳定、消耗低，优先使用。
- 普通 HTTPS：抓列表和详情页的必要字段；限制域名、响应大小、超时和跳转。
- 人工补录：来源无法自动获取但信息重要时，由管理员提供链接或文件。

`robots.txt` 只是技术访问规则，不等于版权或法律授权。启用一个来源必须同时确认网站条款、内容使用范围、访问频率和保存期限。

## 4. Token 与请求消耗控制

1. 先抓标题、时间、来源和链接，不立即把全文交给模型。
2. 对规范化 URL 和正文分别计算 SHA-256；相同内容只抓取和总结一次。
3. 新闻发现缓存 15-30 分钟，政策/统计页面缓存 30-60 分钟，已发布正文按内容哈希长期复用。
4. 只有内容哈希变化时才调用模型生成摘要。
5. 同一事件的多来源先聚类，再生成一份摘要，并保留每个来源证据。
6. 用户查询先读共享摘要；只有明确需要最新状态且缓存过期时才刷新。
7. 实时性按来源定义，不使用一个全局刷新周期：天气可 15 分钟，突发新闻 15 分钟，统计和政策 30-60 分钟。

多用户复用由两级缓存完成：单来源采集缓存避免重复 API/RSS/JSON 请求，多来源 Digest 缓存避免为相同主题重复做合并。Digest 使用哈希键，不把用户主题原文放进公开缓存键；合并阶段不调用大模型。

## 5. 数据边界

新闻观察至少保留：标题、摘要、发布时间、抓取时间、规范化链接、来源 ID、内容哈希、语言、主题和证据。默认不保存广告、评论、用户标识、Cookie、追踪参数或登录后内容。

采集结果进入 HeadCore 前还需要独立的事实融合层：去重、时间排序、来源可信度、冲突标记、过期判断和引用。大模型只能总结已采集证据，不能把自己的常识伪装成当天新闻。

## 6. 启用流程

1. 运行 `scripts/world_source_manifest_check.py` 验证清单。
2. 人工审核一个具体来源的条款、robots、字段和频率。
3. 为该来源实现专用 Adapter 和离线固定响应测试。
4. 只把该来源的 `legal_approved` 与 `enabled` 改为 `true`。
5. 先做单来源 smoke，再接入调度器和事实融合层。

不要一次性开启整个来源清单；当前不提供接受任意 URL 和 CSS 选择器的通用爬虫。
