# HeadCore 认知架构设计基线

## 核心边界

HeadCore 是项目唯一的认知主体。QQ、微信、未来 App 是输入输出通道；ASR、VLM、世界 API 是感知能力；DeepSeek 等模型是 HeadCore 使用的推理与语言能力；TTS 和表情系统是表达能力。

任何外部模型、平台或工具都不能拥有独立的人格、关系、记忆或决策权威。

## 目标流程

```text
观察输入
  -> 更新认知状态
  -> 识别已知与不确定信息
  -> 决定本轮行动
  -> 必要时调用记忆或世界工具
  -> 使用模型组织回答
  -> 评估结果
  -> 保存消息、事件和状态变化
```

## 第一阶段实现

`app/head/` 是 HeadCore 的认知边界，当前包含：

| 文件 | 责任 |
| --- | --- |
| `contracts.py` | 定义统一的 `HeadState`、`HeadDecision` 和 `HeadAction` |
| `state.py` | 复用现有 conversation、self、social 和近期消息构建认知快照 |
| `decision.py` | 决定直接回答、追问、继续任务、修复、支持或拒绝 |
| `projection.py` | 把必要的已知、不确定项和行动目标投影给文本模型 |
| `runtime.py` | 接收统一 `ChannelEvent` 和类型化运行上下文，作为 HeadCore 唯一认知入口 |
| `world_state.py` | 将世界工具结果归类为已知、不确定、需追问、不可用或空闲状态 |
| `communication.py` | 识别沟通行为、维护可撤销的用户状态假设，并生成长度、追问、建议和人格强度预算 |
| `planning.py` | 仅在复杂场景生成有限候选行动，进行多目标评分和风险扣分并选出最终决定 |

第一阶段不新增数据库表。状态由当前受信任数据重建，目的是先稳定契约和行为，再设计持久化，避免形成第二套未经治理的记忆系统。

### 第一阶段沟通策略闭环

当前已加入确定性的多标签沟通状态：回答问题、确认接话、情绪支持、接受纠正、继续任务、话题退缩、请求建议和避免建议。`TurnTakingPolicy` 为每轮提供回答长度、主动性、追问预算、建议预算和人格强度，解决低信息输入仍长篇回复、用户拒绝建议后继续说教、情绪场景过度角色扮演等问题。

“算了、当我没说”等言外之意只形成带证据、置信度和 `needs_confirmation` 的 `LatentIntentHypothesis`。投影明确要求模型不得把心理假设当事实、不得直接写入确定记忆。当前分类来自保守规则，后续只有在标注集和校准评测完成后才替换或补充本地分类器。

Core API 普通/流式聊天、文件音频聊天和 OpenAI-compatible 接口已经接入 `HeadRuntime`。QQ 通过 Core API、Weixin/Hermes 通过 OpenAI-compatible 接口进入同一 Runtime。平台侧的 V2 权限和管理员命令预处理仍在 Runtime 之前执行，这是权限边界，不是第二套认知入口。

## 依赖规则

```text
persona        -> 定义稳定人格与表达边界
mind           -> 提供当前对话、自我和社交状态判断
knowledge      -> 提供审核后的长期记忆投影
world          -> 提供有来源和时效的外部证据
head           -> 统一状态并决定本轮行动
providers      -> 执行模型能力
expression     -> 将决定转换为平台可投递表达
```

`app/head/` 可以消费这些模块的公开契约，但不能复制它们的状态或绕过其权限、质量和审核规则。

## 当前限制

- `HeadState` 是本轮认知快照，尚未跨进程持久化。
- 当前行动选择是保守规则，不是学习型策略。
- 沟通行为和话轮预算目前是确定性规则，尚未使用经过校准的多标签分类模型。
- 当前任务识别只覆盖明显的技术或项目语境。
- HeadCore 已能判断世界证据是已知、不确定、需追问或不可用，但尚未持久保存实体、事件和因果关系。
- 当前没有预测多个候选行动的长期结果。

## 后续阶段

### 第二阶段：状态事件（已开始实现）

当前已通过现有 `ChatRepository` 记忆边界实现：

- `head_task`：保存最小的当前任务文本，支持用户说“继续、接着、下一步”时恢复；
- `head_pending_question`：在胡桃回答结束后记录问题，下一轮用户回复时读取并清除；
- 事件继承现有用户隔离、来源消息、置信度和写入权限；
- 事件类型不进入普通人格记忆投影，只供 HeadCore 内部使用。

仍需继续覆盖：

- 用户明确纠正；
- 关系事件；
- 有过期时间的世界事实。

状态事件应通过现有 repository 边界持久化，不直接在 `ChatService` 拼写数据库记录。

### 第三阶段：世界状态（认识状态已实现）

`HeadWorldState` 已将工具投影转换为 `known`、`uncertain`、`needs_input`、`unavailable` 和 `idle`，并控制能否陈述实时事实。底层 `WorldObservation` 已具备来源、观察时间、有效期、置信度和敏感级别。

持久认知事实的第一版生命周期已经实现：`app/head/cognitive_facts.py` 通过现有 `head_*` 内部事件保存带事实 ID、键、值、来源、观察时间、过期时间、置信度和版本的结构化事实，并支持用户隔离、显式撤销、过期识别和同键多值冲突检测。恢复时只有未过期、未撤销且无冲突的事实会有限投影进 `HeadState.known_context`；冲突、过期和撤销记录保留用于审计，但不会作为确定事实交给模型。

工具原文不会自动写入持久事实。只有通过结构化适配器并显式调用 `save_cognitive_fact` 的数据才能进入该层，事实键和值还受到格式、单行长度和时区时间戳校验。

`app/head/world_model.py` 已实现第一版内存态认知图：`WorldEntity`、带有效时间的 `WorldRelation`、按发生时间排序的 `WorldEvent` 以及 `CausalHypothesis`。关系过期后不再投影，同一主体和谓词出现多个有效对象时转为冲突；未经确认的因果关系始终以“不得当作事实”的假设进入上下文，确认因果要求证据且置信度不低于 0.8。该图层通过 `HeadEventContext -> HeadState -> known_context/uncertainties` 进入唯一认知通路。

`app/head/world_model_store.py` 已通过带 schema 版本和容量上限的 `head_world_model` 内部快照实现跨进程持久化。恢复时重新执行全部引用、时间、冲突和因果证据校验；损坏快照不会进入 HeadState，并可回退到上一份有效快照。写入继续服从关系和输入质量权限，不同用户相互隔离。

当前图层尚未完成世界工具自动结构化摄取、实体合并、事件版本更新和通用时间/因果推理，因此仍不是完整学习型世界模型。

### 长期目标与执行计划

`app/head/long_term_planning.py` 已实现第一版 `HeadLongTermPlan` 状态机。计划由目标、最多 16 个依赖步骤、逐步完成条件、尝试次数和有限重规划预算组成。只有当前活动步骤可以提交结果；成功必须附带完成证据，失败必须附带原因；依赖未完成时不能跳步，达到尝试上限后进入阻塞，超过重规划预算后进入失败。

`app/head/long_term_plan_store.py` 使用 `head_long_term_plan` 内部快照跨进程保存计划，并在加载时重新校验依赖图、当前步骤、证据、尝试次数和重规划预算。恢复后的当前步骤进入 `HeadState.known_context`，阻塞计划进入不确定项。它服务于 HeadCore 的单轮 `HeadPlan`，不是第二个认知主体。

步骤完成证据已经升级为 `HeadExecutionEvidence`，记录证据 ID、来源、可追溯引用、观察时间、成功状态和可选过期时间。只有测试运行器、受信工具结果或明确用户确认可以推进步骤；模型自述、失败结果、空证据、未来时间或在推进时已过期的证据会被拒绝。证据在完成当时有效即可，之后到期不会抹除已经完成的审计历史。

当前仍缺少从自然语言安全生成长期计划、把具体工具执行结果自动转换为结构化证据、用户确认重大重规划以及多目标资源调度。

### 第四阶段：结果反馈

第一版结果反馈闭环已实现：assistant 回复保存最小 `head_last_action`，下一条用户消息确定性识别 `accepted`、`corrected`、`advice_rejected`、`continued`、`stopped` 或 `unknown`，明确反馈保存为 `head_feedback`。纠正和建议拒绝会生成字段受控的 `HeadReflection`，包含错误类型、原因、证据标签、更好行动和候选策略。

反馈和反思继承现有用户隔离与写权限，不进入普通人格记忆投影。单次反馈只修正当前轮策略，不自动升级成永久用户偏好；没有上一行动时不做结果归因。各 Head 事件按类型独立恢复最后一条，避免高频行动事件挤掉低频活动任务。

反馈聚合与短期策略第一版也已实现：只统计最近 7 天且晚于最近 `head_policy_reset` 的反馈；至少两次 `advice_rejected` 才激活建议预算上限，至少两次 `corrected` 才激活歧义澄清偏置。策略包含版本、证据数、原因和过期时间，并可由用户用“恢复默认沟通策略”等明确命令立即重置。短期策略只能降低建议预算和人格强度、增加歧义澄清约束，不能修改胡桃身份、关系权限或长期人格。

仍需继续实现：不同场景分别聚合、评分权重校准和离线反事实评估。只在复杂任务中比较多个候选行动，普通闲聊保持低延迟单次生成。

### 复杂场景候选行动比较

第一版候选行动规划已实现。普通闲聊、blocked 关系和简单回应只保留一个行动；技术任务、明确纠正、重要情绪支持或存在不确定性时，生成最多 4 个候选。候选按意图匹配、任务推进、关系适配、事实可靠性、人格一致性评分，并扣除边界、说教和虚构风险。得分最高的候选转为最终 `HeadDecision`，模型只负责把已选行动表达成胡桃回复。

当前评分是透明、确定性和可测试的策略，不调用额外模型，不暴露自由思维链，也不是 Tree of Thoughts 或 MCTS。

固定复杂场景评测与离线反事实报告已实现：`data/head_planning_scenarios.json` 当前包含 20 个场景，其中加入情绪与任务并存、纠正后继续、拒绝安慰但要求排错等对抗性混合意图；`data/head_planning_pairwise_preferences.json` 包含 10 组人工成对偏好。`scripts/evaluate_head_planning.py` 检查行动选择、复杂度、候选预算、禁止候选和选中风险，并输出选择边际、预期行动分数差、成对偏好准确率和平均 margin。

2026-07-22 基线为 20/20 场景和 10/10 偏好对通过，行动选择准确率 100%，复杂度准确率 100%，平均选中风险 0.0500，平均偏好 margin 0.1460。多评审标注包含 10 项、每项 3 个固定评审身份，共 30 条判断；原始一致率 86.67%，全体一致率 80%，Fleiss’ Kappa 0.8176，规划器对多数共识准确率 100%。

这些评审身份和判断是项目内固定离线评测数据，不等同于已经招募三名真实独立受试者完成实验。结果只证明固定场景集通过，不代表对开放世界复杂任务达到 100% 正确率。偏好数据是可审查的离线规则基线，线上运行不会自动修改评分权重。

下一步应由多名人工评审扩充成对偏好、检查评审一致性，并按技术、情绪、修复和边界场景拆分权重，而不是让线上运行自动修改权重。

### 外部盲评闭环

`app/head/blind_review.py` 与 `scripts/export_head_planning_blind_review.py` 已把固定偏好题转换为可交给真实评审者的匿名 A/B 任务。公开表格只包含用户输入和候选行动目标，A/B 顺序按固定种子逐题随机化；动作枚举、HeadCore 偏好和参考偏好只保存在实验负责人持有的 manifest 中。

`scripts/import_head_planning_blind_reviews.py` 校验匿名评审者 ID、完整题集、A/B 选项、1 至 5 信心值和重复提交，并输出多数共识、原始一致率、全体一致率、Fleiss' Kappa、HeadCore 与多数共识对齐率、逐票胜率和并列数。该结果衡量外部偏好与一致性，不证明 HeadCore 具有人类等价思考或完整世界模型。

## 验收标准

1. 所有平台进入同一个 HeadCore 决策边界。
2. 模型调用前能够观察本轮 `HeadState` 和 `HeadDecision`。
3. 不确定的短指代会追问，明确任务不会被错误拦截。
4. 用户纠正、脆弱情绪和 blocked 关系产生不同的行动决定。
5. 审计只记录行动类型和布尔状态，不记录完整 prompt 或私密上下文。
6. 模型不可用时，HeadCore 状态构建仍可独立运行。
7. Runtime 审计字段能区分 `channel_event` 入口与旧的 `legacy_direct` 调用。
