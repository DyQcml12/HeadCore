# 璃月胡桃 Web 产品设计与研发路线

> 当前版本：2026-07-30  
> 适用范围：`/desk`、`/auth`、`/me` 与 PWA。安全边界、开放状态和 API 事实以根目录完整架构手册为准。

## 1. 当前目标

当前要交付的是一个可连续使用的胡桃网页工作台，不是展示型首页：用户能看懂当前能力、稳定完成文字或按住说话的对话、知道等待发生了什么，并能在账号服务启用后进入完整的账户与记忆流程。

设计优先级固定如下：

1. 对话、输入和错误恢复可用。
2. 账号、会话、记忆和权限边界正确。
3. 三端连续响应式布局稳定。
4. 胡桃、璃月与原神氛围服务于操作，不遮挡内容。
5. 动画、音乐、指针和未来 Live2D 只能作为可降级增强层。

## 2. 已实现的页面与真实边界

| 页面 | 当前职责 | 已经存在 | 尚未可以宣称 |
| --- | --- | --- | --- |
| `/desk` | 普通用户的主要对话入口 | 流式文字、按住说话、能力状态、对话脉络、记忆视图、PWA 壳 | 实时语音通话、浏览器视频对话、全功能 Live2D、跨页音乐不断播 |
| `/auth` | 登录、注册、邮箱验证与密码重置的任务页 | 字段校验、密码显示控制、忙碌锁、错误恢复、开关状态降级 | 在当前本机配置下真实注册、真实登录、真实邮件投递 |
| `/me` | 个人资料、记忆和会话入口 | 本地体验说明、未登录引导、账户资料、记忆删除确认、退出当前会话 | 修改密码、其他设备会话管理、导出、数据删除申请、用户 API Key 管理 |
| PWA | 可安装的 Web 壳 | manifest、静态资源缓存、离线壳 | 原生 App 能力、后台录音、后台长任务 |

`GET /api/v1/auth/status` 是所有账户页的真实状态来源。认证未启用时，表单可以展示和做本地校验，但提交控件必须保持禁用，页面不得伪造“注册成功”或“已经登录”。

## 3. 视觉系统

### 3.1 角色化但不廉价

基础视觉语言来自璃月夜景与往生堂，而非把大面积角色图、泛滥渐变和装饰卡片堆到每个区域：

- 主背景：深夜近黑色，确保文字和消息有明确对比度。
- 主强调：朱砂用于发送、错误与关键动作；鎏金用于身份和可用状态；青玉用于稳定、就绪和低风险提示。
- 结构：细边线、纸张般的暖白文字、低圆角控制件；页面区域不是层层嵌套的浮动卡片。
- 字体：系统中文字体优先，中文、英文、数字和长错误文本都允许自然换行。
- 角色资源：胡桃头像只在其可读、清晰的受控尺寸出现；没有 Web Cubism 运行时与授权前，不用伪 Live2D 宣传替代品。

共享 Token 集中在 `app/static/shared/theme.css`。新页面先复用 `--night-*`、`--paper-*`、`--cinnabar-*`、`--gold-*`、`--jade-*` 和已有控件圆角，不能自行建立互相冲突的紫色、渐变或大圆角体系。

### 3.2 氛围增强层

`app/static/shared/ambient.js` 提供灯火、花瓣粒子、角色呼吸、签条摆动和唱片旋转。它们必须遵守以下规则：

- Canvas 固定在内容下方且 `pointer-events: none`，不阻塞滚动、点击、选字或输入。
- `prefers-reduced-motion` 下减少或停用动画；页面不可见时停止帧循环。
- 自定义胡桃指针只在 `pointer: fine` 的设备启用，并按普通、链接、文本、忙碌、禁用状态回退；触屏不依赖鼠标皮肤。
- 每个可操作元素仍有正常文字、图标、焦点和禁用态，不能靠动态效果传达唯一信息。

### 3.3 音乐

顶栏唱片按钮是一个用户主动打开的网易云纯音乐抽屉。第一次打开才加载跨域 iframe；唱片只在播放器已加载且用户未选择“减少动态效果”时旋转。

跨域 iframe 无法可靠读取网易云的精确播放、暂停或结束状态，也不能绕过浏览器自动播放策略。当前完整页面跳转会销毁播放器，因此不能标注“无缝不断播”。若将来要连续播放，必须先把 `/desk`、`/auth`、`/me` 收进同一个持久应用壳，并重新做无障碍、关闭、静音和移动端验收。

## 4. 三端布局

| 设备范围 | 页面构图 | 必须保证 |
| --- | --- | --- |
| 宽屏桌面 `>=1200px` | 左侧为紧凑角色舞台，右侧为最大的聊天面板 | 聊天区最小宽度 540px；隐藏重复身份栏；角色图不挤压消息或输入。 |
| 平板竖屏 `768px-1199px` | 角色舞台置于聊天上方 | 舞台高度受控；消息、输入和状态独占下一行。 |
| 平板/小屏桌面横屏 `1024px-1199px` | 角色舞台和聊天恢复两列 | 左侧不超过可读比例，右侧聊天仍是主任务。 |
| 手机 `<=767px` | 直接进入聊天，隐藏角色舞台与身份栏 | 固定输入区、底部导航和安全区不互相遮挡；状态可读；操作有触屏尺寸。 |
| 极窄或低高度手机 | 继续压缩装饰和间距 | 不缩小到无法输入或无法看到发送、按住说话、Toast。 |

布局验收不是三张静态截图。至少从 320px 连续拖动到 1920px，并分别检查 390x844、1024x768、1440x960：`document.documentElement.scrollWidth` 不大于 `window.innerWidth`，没有遮挡、无意义空白或文字溢出。

## 5. Desk 交互规格

### 5.1 可用性状态

页面加载后分别检查：

| 能力标签 | 状态来源 | 显示含义 |
| --- | --- | --- |
| 文字对话 | `/health` | Core 可达时显示已连接；失败时暂停发送并提示重试。 |
| 按住说话 | 浏览器 `getUserMedia` 与 `MediaRecorder` | 仅表示浏览器具备录音能力，不等同于 ASR 已可用。 |
| 回复语音 | `/api/v1/voice/status` | 仅表示受保护的 TTS 播放条件；默认未启用。 |

能力标签只能展示真实状态。不可用功能保持解释，不放一个点了必然失败的假入口。

### 5.2 文字对话

1. 用户输入文本，`Enter` 发送，`Shift+Enter` 换行；输入区高度有上限并保持页面稳定。
2. 提交后立即追加用户消息，锁定提交、模式切换和录音操作，防止同一请求重复发送。
3. 在第一个有效流式片段前显示独立的“正在思考 · 耗时”小状态；它不是胡桃消息。
4. 通过 `POST /api/v1/chat/stream` 逐段呈现回复。流式中断时保留中断状态，显示可理解的失败提示并恢复输入。
5. 若服务端返回有效 `reply_id` 且公开 TTS 已启用，才在该回复旁显示按需播放按钮。

### 5.3 按住说话

1. 文字与语音是同一个输入区的两种互斥模式，避免上传、录音、发送三个同类控件并列。
2. 按下后请求麦克风；用户松开、取消或键盘释放后停止录音并关闭媒体轨道。
3. 单个 Blob 通过 `/api/v1/audio/chat/file` 提交，服务端转写后进入同一 HeadCore 链路。
4. 页面显示“正在听你说”的独立等待状态，成功后将语音气泡替换为转写文本；失败时提示重新说一次。

这是一段式语音消息，不是实时 ASR、持续语音电话或视频通话。浏览器不支持、用户拒绝权限、ASR 质量不足、模型不可用都必须显式失败，不得伪造结果。

### 5.4 对话脉络与记忆

- “对话脉络”读取 `/api/v1/dialogue-context`，只展示当前状态、正在跟进事项和待确认问题。
- “记忆”读取当前会话授权范围内的内容；账号模式下后端从会话推导 profile，本地体验模式只限当前浏览器。
- 删除记忆必须进入原生确认对话框。删除成功后刷新列表；失败、未登录或服务不可用必须保留可恢复提示。

## 6. 认证与个人中心

### 6.1 `/auth`

登录、注册、验证和密码重置共享一个任务容器，只有一个当前视图；不叠加两套密码显示控件，不在公共入口展示“返回对话”这类绕过认证逻辑的按钮。

- `return_to` 仅接受以单个 `/` 开头、且不以 `//` 开头的站内路径，避免开放重定向。
- 显示/隐藏密码是单个输入框的类型切换，不复制或同步第二个密码框。
- 提交期间整张表单进入忙碌锁；服务状态关闭时保留字段说明、禁用提交按钮。
- 验证完成后回到登录是验证流程的一部分；登录成功后才转到安全的 `return_to` 或 `/desk`。

公开认证仍依赖 MySQL V2、邮箱服务、会话、CSRF、限流与真实联调。当前页面的目标是诚实降级，而不是让本地演示看起来像已经可注册的生产站点。

### 6.2 `/me`

个人中心不是“个人手札”式展示页，而是账户与记忆的操作页：

- 认证关闭：显示本地体验模式，说明文字对话与按住说话可用、数据不跨设备同步。
- 认证开启但未登录：只显示登录引导，不泄露其他账户信息。
- 已登录：提供账户资料、当前账号记忆、安全与当前会话退出；记忆删除有确认。
- 暂不显示用户填写 Provider Key 的文本框。未来支持时必须使用服务端加密、只显示末尾掩码、不可回显原值、可撤销并有审计。

## 7. 网页与后端的对应关系

| 前端能力 | 后端接口 | 当前公开边界 |
| --- | --- | --- |
| 文字流式回复 | `POST /api/v1/chat/stream` | 认证开启后要求会话与 CSRF；本地体验只用于开发。 |
| 非流式兼容回复 | `POST /api/v1/chat` | 不是 Desk 的首选路径。 |
| 语音消息 | `POST /api/v1/audio/chat/file` | 认证开启后要求会话与 CSRF；需要真实 ASR 验收。 |
| 对话脉络 | `GET /api/v1/dialogue-context` | 认证开启后从服务端会话获取 profile。 |
| 记忆 | `GET /api/v1/memories`、`DELETE /api/v1/memories/{memory_id}` | 删除要求 CSRF 与 profile 限定。 |
| 认证能力状态 | `GET /api/v1/auth/status` | 始终可读，只返回布尔状态。 |
| 账户 | `/api/v1/auth/*` | 依赖 MySQL、认证和 SMTP 的条件注册。 |
| 短时胡桃 TTS | `GET /api/v1/voice/status`、`POST /api/v1/voice/synthesize` | 默认关闭，认证、回复 ID、限流和模型验收缺一不可。 |

摄像头、屏幕识别、视频对话、控制中心、世界工具管理和系统配置不属于普通 `/desk`。视觉工作台只面向受保护的本地管理员会话。

## 8. 当前研发顺序

### P0: 把 Web 主路径做成可验收闭环

1. 对 Desk、认证和个人中心完成浏览器回归，覆盖宽度连续变化、键盘、触屏、拒绝麦克风权限、网络中断、长文本和错误恢复。
2. 用 Docker MySQL 应用迁移，验证两个账号之间的会话、记忆与删除操作完全隔离。
3. 只对受控邮箱完成注册、验证码、密码重置、过期、重放和登录的真实 SMTP 联调。
4. 补齐账户闭环：验证码重发、修改邮箱、异常恢复、会话列表与撤销、登录记录、记忆导出和数据权利申请。

### P1: 公开前的安全与运维

1. 完成域名、HTTPS、反向代理白名单、控制面隔离和上传大小限制。
2. 实现邀请码/审核、账号配额、成本熔断、共享限流、备份、恢复和回滚演练。
3. 在上述能力通过后，再对少量用户开放封闭测试。

### P2: 受控能力完善

1. 实测按住说话、ASR 和短时 TTS 的真实性能与失败路径。
2. 按来源许可逐项启用世界证据工具，并记录真实 API 验收。
3. 继续评估 HeadCore 长对话、长期计划和人格一致性；不把有限世界状态宣称为通用世界模型。
4. 若产品决定允许用户自带 API Key，先实施加密凭据系统、掩码、撤销、审计和额度，之后才增加 UI。

### 暂停项

微信小程序、原生 App、Live2D 桌宠、游戏屏幕识别和视频对话目前暂停。它们只能在网页公开主线、账户安全和运维验收完成后重新立项，不能占用当前 Web 闭环的开发资源。

## 9. 完成标准

网页不是“页面能打开”就算完成。至少要同时满足：

- 三端宽度连续测试无横向溢出、遮挡、固定空白或难以点击的控件。
- 文字、语音、思考状态、错误、重试、记忆、注销与本地模式都呈现真实状态。
- 认证未开时没有假成功；认证开启后由服务端会话和 CSRF 决定身份。
- 动画、音乐、角色图和鼠标皮肤被关闭、阻止或不支持时，核心对话仍完整可用。
- 浏览器控制台没有项目错误；无障碍焦点、键盘与减少动态效果行为通过人工验收。
- 真实 MySQL、SMTP、模型、TTS、HTTPS、限流、备份和隔离要求满足后，才允许称为可对外开放测试。
