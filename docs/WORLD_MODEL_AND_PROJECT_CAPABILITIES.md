# HuTaoChatCore 功能与世界模型关系说明

更新时间：2026-07-25

## 1. 结论

HuTaoChatCore 当前**没有已训练、可自主模拟现实的通用世界模型**。项目中的“世界”是 HeadCore 的受控证据工具层：当用户明确提出天气、地点、路线、新闻或政策问题时，系统从经过配置和许可检查的数据源取得有限事实，再把带来源的结果交给 HeadCore 组织回答。

这意味着：

- 文本模型负责理解和表达，不等于拥有实时世界知识。
- 地图、天气、新闻和政策适配器负责取证，不等于人格、记忆或决策主体。
- HeadCore 是唯一认知主体，`hutao_v1` 是运行时人格。
- 未配置、未批准、未明确请求或存在歧义时，系统应说明不可用或请求确认，不能编造事实。

## 3. 项目功能与世界层的关系

| 项目功能 | 所属模块 | 与世界层的关系 |
| --- | --- | --- |
| 文字对话 | `app/services/chat_service.py`、`app/head/` | 世界上下文是可选输入，不会替代聊天、人设和记忆。 |
| 人格与表达 | `app/head/`、`app/expression/` | 由 `hutao_v1` 与文本 Provider 完成；世界工具只提供事实边界。 |
| 记忆与关系 | `app/storage/`、`app/knowledge/` | 保存用户关系和允许持久化的内容；不能把外部原始网页、密钥或精确位置直接写入记忆。 |
| 语音 | `app/audio/`、TTS Provider | ASR/TTS 是输入和表达能力，与世界工具独立。 |
| 视觉/相机 | `app/camera/`、本地 VLM/OCR | 是本地感知能力；不进行人脸识别，也不是世界模型。 |
| 世界证据 | `app/world/` | 在明确请求、配置、许可与同意满足时，提供天气、地点、路线、新闻、政策的结构化证据。 |
| 控制中心 | `app/control/` | 只读展示世界工具是否启用、配置与许可是否齐备；刷新不调用外部 API。 |

## 4. 当前世界工具

| 能力 | 实现 | 数据源/模型类型 | 触发与限制 |
| --- | --- | --- | --- |
| 行政区、地点、路线 | `app/world/adapters/amap.py` | 高德 Web Service API，不是模型 | 路线属于精确位置能力，必须由明确路线请求和同意触发。 |
| 当前天气、预报 | `app/world/adapters/qweather.py` | 和风天气 API，不是模型 | 必须启用、配置 API Key、确认许可；地点不清楚时请求确认。 |
| 新闻摘要 | `app/world/adapters/news.py`、`news_digest.py` | GDELT、官方 RSS 等信息源，不是模型 | 来源逐项启用和许可批准；不抓取不受控全文。 |
| 政策更新 | `GovCnPolicyAdapter` | 政府公开元数据源，不是模型 | 默认受许可与启用开关约束，保留来源 URL 和时间。 |
| 事实整理与冲突提示 | `app/world/context.py` | 确定性规则，不是生成模型 | 限制条目数、字符数、过期数据和来源；检测天气等冲突。 |
| 请求判断 | `app/world/brain.py` | 确定性意图/边界规则，不是模型 | 仅识别明确请求；用户拒绝、普通提及或系统主动触发会被拒绝。 |

## 5. 使用到的模型与工具

### 5.1 认知与表达模型

文本 Provider 由 `MODEL_PROVIDER`、`MODEL_NAME` 等配置决定，当前代码支持的运行路径以 `app/providers/` 和 `app/expression/` 为准。它用于理解用户输入、维持胡桃的表达和输出回复；它不是世界数据来源。

### 5.2 感知与语音模型

- ASR：`app/audio/` 中的 FunASR/SenseVoice 预设，用于音频转写。
- TTS：本地 GPT-SoVITS、CosyVoice 等表达 Provider，用于语音输出。
- 视觉：Ollama VLM 或 OCR，以及 `app/camera/` 的本地受控感知路径。

这些模型都可能影响“看见、听见、说出”的能力，但不构成现实世界的持续模拟。

### 5.3 世界数据工具

- 高德：地图、行政区、地点、路线。
- 和风天气：当前天气和天气预报。
- GDELT、联合国/WHO RSS、政府政策元数据：候选新闻/政策证据源。

API Key 只留在 `.env` 和适配器内；不得写入前端、文档、日志、缓存键或聊天记录。

## 6. 安全与运行规则

1. 世界功能默认由 `WORLD_AWARENESS_ENABLED` 控制。
2. 每个数据源同时需要启用与法律/条款批准；只有 API Key 不足以执行请求。
3. 精确路线和公开 IP 定位需要显式同意；系统不从请求 IP 猜测用户位置。
4. 外部数据是不可信输入，只能经过 `WorldContextAssembler` 的长度、来源和过期控制后进入模型上下文。
5. 所有相同查询经 TTL 缓存和并发合并处理；缓存键不会包含原始敏感参数。
6. 控制中心只显示布尔状态和数量，不显示 Key、Token、原始位置或外部响应内容。

## 7. 当前阶段与后续方向

当前阶段是“可审计的世界证据工具”，不是 AGI 世界模型。下一步应优先完成：正式用户会话、数据源许可审查、真实 API 的受限验收、世界证据的用户可见引用和错误解释。只有在有明确数据、训练目标、评估集、成本预算和安全边界后，才应讨论训练预测/模拟类世界模型；在那之前不应将接口聚合包装为世界模型。
